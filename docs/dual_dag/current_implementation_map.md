# Current CRAFT Dual-DAG Implementation Map

This map is the Phase 0 inventory for the multi-benchmark Dual-DAG extension. It records the existing CRAFT implementation before any benchmark-neutral interface work. Future changes should reuse or wrap these components unless a regression-protected change explicitly replaces them.

## Scope

- Benchmark covered: CRAFT only.
- Primary implementation root: `benchmarks/craft/`.
- Existing Dual-DAG root: `benchmarks/craft/dual_dag/`.
- Current data model: mixed dataclasses at extraction boundaries and dict-based runtime/artifact records.
- Required constraint: do not create a second CRAFT Dual-DAG runtime, candidate lifecycle, leakage checker, or artifact schema with overlapping responsibility.

## Data Shape Notes

- CRAFT runtime graph state is mutable and dict-based inside `DualDAGRuntime`.
- Extraction helpers use dataclasses at the edge, then serialize into dicts for runtime storage and artifacts.
- Existing action candidate states differ from the proposed broader lifecycle. Common lifecycle work must include an explicit compatibility table rather than renaming CRAFT states.
- Current CRAFT action edges include `conflicts_with`. Future non-CRAFT DAG implementations should not infer that conflicts must be DAG edges; keep CRAFT artifact compatibility separate from general graph constraints.
- Current visibility is not agent-set based. It is provenance-level string metadata and leakage guard denylist checks.

## Regression Dependencies Before Refactor

Before changing the CRAFT runtime or artifact schema, protect at least these behaviors:

- Observation visibility and Director isolation.
- Reported claim extraction and uncertainty markers.
- Candidate generation, support, conflict, required evidence, and confidence.
- Candidate lifecycle transitions and executed-action marking.
- Clarification gate decisions, VOI diagnostics, cooldown/limit behavior, and clarification outcomes.
- Public retrieval metrics and decision-support metadata.
- Normalized artifact names, schema version, and metric field names.
- Hidden state key sanitization and leakage report behavior.

## Recommended Next Actions

1. Freeze a deterministic CRAFT regression fixture before modifying any runtime behavior.
2. Add a minimal benchmark-neutral adapter Protocol that wraps CRAFT outputs without moving `benchmarks/craft/dual_dag/`.
3. Add common visibility/source provenance beside the existing leakage guard, then instrument one prompt/artifact path at a time.
4. Defer C-WAH adapter implementation until the C-WAH source audit is complete.
